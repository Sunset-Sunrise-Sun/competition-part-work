## 结论

适合借鉴动作分析与可视化设计，不能直接替代 LocalFit 的离线运行、健康计划和热量估算。重点借鉴个人/机位校准、次数与幅度分离、逐次升降节奏、结构化证据和失败处理。训练示例采用云端网关及视频/图像上传；代码开源不代表推理离线或所有模型权重采用同一许可。本次未发现卡路里或 MET 能耗计算模块。

## 1. 动作识别：先区分三件事

姿态估计回答关键点在哪里，类别识别回答正在做什么，阶段分析回答该动作完成到哪一步。上游训练示例和当前 LocalFit 都主要针对已选动作分析，不是通用活动分类器。

比赛先由用户选择动作，系统验证机位和完整周期。自动类别识别未来可基于关键点时序小模型，必须包含 idle/unknown，避免把整理衣服或弯腰误认为训练。先用标注回放验证误识别，再扩充第三动作。

## 2. 次数、幅度和正确性分开

上游 pull_ups 独立记录次数和幅度，浅动作也可以计数，再评价两端幅度。LocalFit 采用独立实现的深蹲基线：先见到站立区间再启动候选周期，用下降/返回双区间完成计数，再按当前实验阈值记录幅度。

本次实现 `within_rule / below_rule / unobservable` 三态，分别表示达到实验幅度、未达到、不可评价。它们不等于动作安全/危险或生物力学正确。上游某些不可见端点按未达标处理，我们保留 unknown 状态，避免把检测失败归因于用户。

逐次记录开始、最低点、结束、下降和起身耗时、最低角度与幅度状态，界面与后端报告保留最近 100 次。开始时间是进入实验角度区间后的时间，不是精确运动起始点；平滑会影响极值和节奏，必须通过标注验证。暂停不进入活动时钟；超过 500ms 观察缺口丢弃未完成候选，不能在长缺口插值后强判。

## 3. 宽高比是实际修正项

MediaPipe x/y 分别按画面宽高归一化，不能直接当成相同长度单位算角度。此次 `jointAngle` 先把 x 差乘画面 width/height，再求二维角度。Worker 回传实际 ImageBitmap 的宽高比；躯干水平/垂直比也校正。

这解决非方形画面的几何尺度问题，不解决单目投影、摄像头方向或关键点偏移。上游 COCO-17 与我们 MediaPipe-33 的编号不同，后续替换姿态模型必须显式映射，不能直接按数组下标接入。

关键映射参考：COCO shoulder 5/6 → MediaPipe 11/12；elbow 7/8 → 13/14；wrist 9/10 → 15/16；hip 11/12 → 23/24；knee 13/14 → 25/26；ankle 15/16 → 27/28。缺失的额外关键点必须标不可见；COCO score 不应未经验证等同 MediaPipe visibility。

## 4. 校准应绑定用户、动作与机位

上游记录参考动作的统计量、来源和版本；更换用户或机位需重新校准。对我们有意义的合同：profile_version、exercise、camera/setup、模型版本、站立/最低膝角、躯干尺度、有效样本数、分散程度和审阅状态。

参考动作需用户确认并尽量由有训练经验者审阅。若差异过大或遮挡，拒绝保存校准。个人做得最深的一次不自动成为“正确深蹲”。校准是待实现任务，本次只完成固定规则的单次幅度与时序记录。

## 5. 实时与离线算法不能直接互换

上游部分计数采用居中滤波、完整片段幅度统计和插值，这些可能读取未来帧或整段数据。适合离线回放，不能直接声称实时无延迟。我们的当前引擎采用因果平滑、已有历史和缺口拒绝；后续保存原始摘要用于组后更精细复盘。平滑系数仍按帧，跨 FPS 可比性待改成按时间参数并评测。

建议做对照：同一授权回放 → MediaPipe 本地姿态 → 实时规则；可选 4090 本地 ViTPose → 同一归一化接口 → 同一规则。比较关键点失败、计数、误报、时延与资源，不仅比较演示观感。没有需求授权时，不调用上游云端 API 上传真实用户视频。

## 6. 卡路里计算保持独立模块

本次源码与说明的关键词核查未找到 calorie/kcal/能耗模型，因此不能写“已接入该项目的热量算法”。逐次节奏能帮助分段或查强度，但仅凭姿态、次数或相似度无法精确推断个体代谢；负荷、体重、肌肉募集和生理反应都会影响结果。

路线：动作/强度映射 → 区分训练和休息时长 → 用户体重 → MET 场景 → 总/净消耗及不确定性说明。运动总 kcal 约为 Σ MET×kg×小时；净活动消耗需扣除同时间静息口径。可穿戴心率只能作为辅助，不是无误差真值。无测量真值不报告能耗准确率。

当前后端仍按运行活动时钟和演示 MET 区间估算，尚未自动分出站立/休息，原地停留可能高估。此次单次时间数据是后续分段的基础，不能直接把候选周期时长当作全部运动生理时长，也不能用次数×固定 kcal。

## 7. 许可与复用

上游源码标 Apache-2.0。本次只参考设计和源码评估，没有复制或打包上游实现；LocalFit 的独立实现仍属本仓库原创代码。若后续移植源代码，保留上游许可证、相关版权和适用 NOTICE，标明修改；不能把上游代码全部改标 MIT。API 服务条款、模型权重和视频素材许可分别核对。
